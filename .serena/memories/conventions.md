# Conventions

Full rules are in `AGENTS.md` (sections 1–7). Key points:

- Kernels are `static __attribute__((noinline))`, take `(data, len, n_reps)` (Test 3's `dispatch_sequential(n)`/`dispatch_random(idx, n)` make `n` calls) and return a value that gets consumed: through `anti_dce_sink(u64)` or an observable check (Test 4 compares branch and branchless sums).
- Measure only via `MEASURE(result, kernel(args))`: it runs the `-n` trials (warm-up only when trials > 1) and returns the median trial; `MEASURE_ONCE` wraps one call as perf_start → timer → kernel → timer → perf_stop. Nothing else goes between the two `now_ms()` calls: no allocation, RNG, I/O or syscalls. Keep it a macro so kernels are called directly.
- A reported row is one real trial, never a per-field median.
- Guard each `r.counts[CTR_*]` slot with `perf_has(CTR_BRANCHES|CTR_MISSES|CTR_CYCLES)`; any may be missing. Open counters are tracked in `perf_open_mask` (zero = none open), never by `perf_fd[]` values. New counter: one row in `FOR_EACH_COUNTER` (generates the `CTR_*` slot and its `counter_descs[]` entry: slot, `PERF_COUNT_HW_` suffix, ARM raw code, Markdown header, console label/width), its place in `counter_display_order[]` (`CHECK_LEN` fails the build on a wrong length), and an entry in `fake_perf.c`'s `fake_events[]` (`FAKE_PERF_EVENTS` name).
- Output per test, after all `MEASURE` calls: `const Work work = { count, "elem" | "call" }`, `const ReportRow rows[]`, then `emit_pair_summary(report, title, desc, rows, &work)` for 2-row tests, or `emit_rows` + `emit_ratio` per ratio + `print_miss_cost` + `printf("\n")` (Test 4). Labels may carry extra spaces for console alignment; `report_table()` collapses them in Markdown.
- Each `run_testN`: `const size_t len = size;` first, setup before measuring, free everything at the end. New test: bump `NUM_TESTS`, add `if (test_selected(N)) run_testN(report);` in `main`, extend `smoke_test.sh`'s `for t in 1 2 3 4` loop and move its `expect 1 -t 5` out-of-range case.
- Randomness only from xorshift64 `rng64()` / `rng_state`, never `rand()`.
- Test 3 leaves: `FOR_EACH_LEAF(DEF_LEAF)` / `PTR_LEAF`, each XORs with its own constant (leaf number × Weyl step) so ICF can't merge them; keep `NUM_FUNCS` in sync. (GCC does fold `sum_branch` into `sum_threshold`: identical bodies, harmless.)
- CLI: options handled one at a time in `apply_option()`; numeric values via `option_number()`/`parse_count()` (range-checked, K/M suffixes). Keep functions small: SonarQube Cloud flags cognitive complexity > 25.
- Types: `u64`/`u8`; format u64 with `PRIu64`, `size_t` with `%zu`; `L`/`UL`/`ULL` suffixes uppercase (SonarQube S818 flags lowercase `l`); lowercase `u` (`1u`) is used and accepted. Integer→`double` conversions always as explicit `(double)` casts (SonarQube S5276), also in mixed arithmetic like `100.0 * (double)a / (double)b`.
- Style: 4-space indent, K&R braces, section-banner comments (`/* ── Title ─── */`), aligned `#define` comments, `static` on every file-scope symbol.
