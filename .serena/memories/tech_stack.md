# Tech stack

- C99 (`-std=c99`, enforced by `run.sh`), one translation unit. `#define _DEFAULT_SOURCE` must stay before the first include: it exposes POSIX/Linux APIs (`clock_gettime`, `localtime_r`, `fdopen`, `syscall`). `_POSIX_C_SOURCE` alone hides `syscall()` and breaks the build.
- Headers: stdio/stdlib/stdint/string/time/inttypes/fcntl/unistd always; on Linux also sys/syscall, plus linux/perf_event and sys/ioctl when `__NR_perf_event_open` exists (`HAVE_PERF`).
- Compilers: gcc is the reference (`run.sh`). clang builds only with `-fno-vectorize -fno-slp-vectorize` (no `-fno-if-conversion`) and (clang 18–21) makes Tests 1, 2 and Test 4's branch variant branchless (cmov in `sum_threshold`/`sum_branch`, sbb in `count_decisions`), so its timings are invalid; use it for warnings/analyzer only. No Makefile/CMake, no package manager. Needs POSIX; not MSVC. On Windows, build and run inside WSL2; `.gitattributes` keeps `*.sh` LF so the scripts run there from a Windows clone.
- Required flags (never drop): `-O2 -fno-tree-vectorize -fno-if-conversion`. Without them the kernels get vectorized or made branchless (cmov, setcc/sbb) and the mispredictions disappear. Tests 1–3 and Test 4's branch variant need them; Test 4's branchless variant doesn't.
- Perf: `perf_event_open(2)`, user mode only, one group of branches/misses/cycles read with `PERF_FORMAT_GROUP` (+ time enabled/running, scaled if multiplexed). Unavailable with restrictive `perf_event_paranoid`, in most containers, and in VMs without a virtual PMU (both VPS runs in RESULTS.md); WSL2 can expose them (the Ryzen 9600X run has hardware counts). Otherwise wall-clock only (`now_ms()`, monotonic).
- Clock info: max clock from `/sys/devices/system/cpu/cpu*/cpufreq/cpuinfo_max_freq` (highest across CPUs); measured average from cycles ÷ time.
- Code quality: SonarQube Cloud (public project `juusolatva_branch_bench`), scanned from the CI `sonarqube` job (Build Wrapper + gcovr coverage; Automatic Analysis off). Quality gate on new code: coverage ≥ 80%, duplication ≤ 3%, severity score ≤ 14 for code smells and ≤ 9 for bugs, vulnerabilities and SCA. The scan waits for the gate (`sonar.qualitygate.wait=true`), so a failed gate fails the CI sonarqube job; `main` has no branch protection. With no `sonar.projectVersion` the new-code period (previous_version) never advances. Check it via the `project_status` API (`mem:suggested_commands`). The user marks false positives in SonarQube Cloud.
- CI: GitHub Actions, hosted runners (Ubuntu 24.04 VMs, no PMU/cpufreq) — correctness and codegen only, never timings. CI compilers (GCC 13.3, Clang 18.1) are older than local ones, so a CI codegen pass doesn't cover the local build; check local disassembly too.
- Results so far (RESULTS.md): NEW — Haswell i7-4770, Kaby Lake R i5-8350U, Raspberry Pi 4 (Cortex-A72); OLD format — Ivy Bridge i5-3380M, Zen 5 Ryzen 9600X (WSL2); VPS (wall-clock only) — EPYC-Rome, Xeon (Skylake). Planned: Cudy WR3000S (Cortex-A53, OpenWrt). Dev machine: Fedora Linux x86_64 (i5-8350U).
